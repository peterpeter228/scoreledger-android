# dot 工作流与权限边界

## 已核实与不能推断
OpenAI 文档说明 dot 可用自己的云电脑处理软件任务，电脑有自己的文件与会话；连接工具和动作受权限控制 [S01–S03]。
这不证明本用户的 dot 已安装 Android SDK、支持硬件虚拟化、能访问真机、已登录 GitHub 或能代用户签署声明。
本包不发明“dot项目导入API”或专用配置格式。普通ZIP+文本入口，通过当前实际可用工具读取。

## 运行前能力矩阵
在 `evidence/environment.json` 写入真实探测结果：OS、Java、Kotlin、Gradle、SDK/BuildTools、磁盘、网络、
模拟器及 /dev/kvm（若适用）、adb已授权设备、git状态、GitHub连接可读/可写、可否获取附件字节。
禁止打印所有环境变量/完整登录信息。只记录工具存在、版本与非敏感错误摘要。

## 三条构建路径，按顺序尝试
A. dot云电脑能安装并运行JDK/SDK：本地构建，能用模拟器才做模拟器测试。
B. 云电脑可写本项目已授权仓库但无法运行SDK/虚拟化：代码提交至明确仓库，使用包内CI产物。
C. 云电脑缺少执行/外部权限：完成文件和纯业务可执行检查，交付工程与阻断清单，不假称APK存在。
遇到B路径需权限时遵守审批，不凭“读取仓库成功”认定有写入/Actions权限。
不存在本项目仓库时不得擅用过去项目；先在工作目录完成A或C，不因仓库缺失停工。

## 长任务和上下文
`PROJECT_STATE.json` 是项目状态，不依赖聊天记忆作为唯一事实源。
每阶段把下一步、失败命令、未提交变更、产物路径和待决事项写 `tasks/HANDOFF.md`。
委派：主代理维护PRD/核心/合并；其他代理只认领UI、导出、测试等独立文件范围；先定接口再并行。
架构/数据schema同一时刻只由一个代理修改。审查者可以不写代码，仅出可复现问题。

## 更新策略
按里程碑而非每个终端命令通知用户：环境完成、首个APK、P0回归、最终交付。
遇真实账号/付款/权限阻断集中请求最小必要动作。不要索取明文密钥，不指示用户关闭所有安全规则。
文档说明的dot持续任务能力，不代表本次制作文件的聊天助手承诺稍后自动交付。

## 连接器故障
同一失败最多一次原样重试；之后分类：权限、审批、网络、超时、限额、大小、状态冲突。
若需要GitHub写入且工具支持，使用小批次/标准git路线，必须核对commit、ref和工作流run ID。
blob创建、tree创建、commit创建、分支指向、CI触发、APK上传是六个不同事实；不可跳步报喜。
不要把与本任务无关的私有仓库/邮件作为资料传给外部审查模型。

# 验收测试计划

## 测试分层
1. 纯Kotlin core：原始分解析、状态、加权汇总、比较门禁、权益数量。
2. 独立Python契约：JSON结构和跨引用/异常导入。与Kotlin实际导入器共用fixtures，不能永久拿Python替代安卓导入测试。
3. Room仪器化：父子事务、外键、编辑、删除、导入回滚、migration。
4. Compose/设备：录入、返回、旋转、键盘、大字体、深色、无GMS、文件选择/分享。
5. 商业：真实测试商品购买/恢复/撤销。必须在渠道测试环境运行。

## 数据样本
全为虚构昵称和记录，不使用用户实际孩子数据。fixtures里有有效与空备份；reference测试在内存变异生成非法输入。
规模测试另生成20孩子/100科目/10,000考试/100,000成绩上限；注意每次最多30科，不让样本自相矛盾。
长中文/全角数字/0分/满分变更/缺考/未录入/跨孩子同名科目/同日考试/闰日都需覆盖。

## 设备矩阵
模拟器API26、30、36；实际用户安卓设备优先；另至少一台无GMS和一台有GMS设备。
系统厂商/版本、RAM、键盘、字体缩放、方向写证据，不能用“安卓已测”泛化。
若本环境无模拟器/真机，状态NOT_RUN，绝不把截图原型当执行证据。

## P0失败定义
丢失已提交记录、串孩子、0与缺失混淆、统计计算错误、导入覆盖失败不能回滚、购买未确认即解锁、
基础导出被权益锁、敏感数据外发、发布密钥泄露，任一出现都不得商业发布。

## 手工故障注入
- 保存按钮连点10次；只出现一个UUID；进程在事务前/中/后被杀的行为分别验证。
- 导出目标存储写满/取消/URI撤销；不能报成功，原库不变。
- 恢复前在内存校验后故意破坏文件/中断写库；只能旧库或完整新库，不能混合。
- 备份恢复到新安装后逐表计数与统计比较；重复恢复不翻倍。
- 退款/无网络/切换账号；旧数据始终可带走。

## 证据格式
每个用例标not_run/pass/fail/blocked，附设备、日期、版本、命令、日志、截图或步骤；
issue编号回链，修复后重复原case与相邻case。未执行数量必须明确，不能只写“全部通过”。

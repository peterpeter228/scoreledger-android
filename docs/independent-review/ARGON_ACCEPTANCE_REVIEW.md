当前三端均未达标（API26: 46/51，API30: 45/51，API36: 47/51）。主流程、版本升级及静态持久化等局部通过，**绝不等同于全量通过**。严禁将任何失败项改为 `@Ignore`/skip，或退化为“仅验证不崩溃/截图存在”。

### 一、 拟修方案评判：合理契约更新 vs 掩盖真实Bug风险

*   **A（备份目录冲突）：合理更新，需防静默失败。** 细化错误分类并核对原库完整不变是合理的；但须确保生产代码不是简单吞掉IO异常，而是真正在恢复前置校验中拦截并触发了UI错误态。
*   **B（PDF预览校验）：合理更新，但有漏测风险。** 改用 `ReportManager.generate` 真实产物符合端到端契约，不放宽生产校验正确。但直接替换会丢失对“非法文件名拦截”的验证，必须拆分保留反向测试。
*   **C（PDF渲染断言）：存疑，可能掩盖生产环境Bug。** `PdfRenderer` 渲染在透明 Bitmap 上导致全0（黑），若生产预览组件已填白而仅测试漏填，属合理修正测试；但须核查生产代码（尤其API30）导出或预览时是否同样缺失 `Color.WHITE` 底色初始化。通过标准必须包含：边距纯白、深色文字像素>1000及文本行完整。
*   **D（取消限制与新上限）：合理契约更新。** 适配“取消3场考试限制”及“20孩上限”属正常演进，保留幂等与非法回滚断言合理。
*   **E（异步等待Editor）：警惕掩盖性能退化与状态丢失。** 禁用 `sleep`、改用条件等待是正确的，但严禁无限等待。必须绑定 `IdlingResource` 或设严格超时（如3秒），并排查编辑点击到 Room 发射状态之间是否存在主线程卡顿或初期无 Loading 态的交互缺陷。
*   **F（系统文件选择器）：合理兼容适配。** AOSP 26/30 的 DocumentsUI 节点无 clickable 属系统差异。回退到真实 bounds 触屏点击、保留UI树/截图转储且不 Mock URI 回调，保证了SAF全链路真实性。
*   **UI与Insets（键盘遮挡/图表）：高风险，对齐Host可能掩盖组件缺陷。** 仅对齐测试 Host 配置会掩盖“通用编辑组件自身未处理 WindowInsets 而强依赖宿主 Activity 配置”的隐患。必须在真实 `MainActivity` 弹起键盘时，硬性断言保存按钮 `bottom <= IME.top`。图表坐标对齐属合理视觉修复。

### 二、 必须保留的4个反向验收用例（硬性阻断）

1.  **非法报告ID拦截（源自B）：** 保留传入伪造非UUID文件名（如 `../native-preview-xx.pdf`），断言预览器明确拒绝加载并抛安全异常，防止路径穿越。
2.  **备份恢复异常回滚（源自A）：** 当备份目标路径被非目录文件占用或只读时，断言恢复中止、弹出准确错误文案，且原 Room 库全表记录与 Baseline 逐字节一致。
3.  **资源上限与事务回滚（源自D）：** 断言第21个孩子创建被拒，且构造第4场考试的“非法编辑/越界分数”提交，断言被拦截且原库中前4场有效记录及草稿未被污染。
4.  **UI编辑中真实Process Death恢复（补充）：** 鉴于当前仅测了外部 `force-stop`，必须在编辑页输入未保存草稿、键盘弹起状态下，模拟系统回收重建（如 `ActivityScenario.recreate()` 或杀死后台进程后回前台），断言草稿数据不丢失且保存按钮不被键盘遮挡。

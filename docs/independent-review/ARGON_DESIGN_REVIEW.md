以下是针对 ScoreLedger 版本 2 修复计划的 6 项最高危遗漏审查：

**1. 备份流式解析缺失导致 OOM 与逻辑炸弹绕过**
*   **风险**：允许最高 96MiB JSON 备份，若一次性加载到内存进行 DOM 解析及“重复键/引用”验证，在低配设备或 API 26 模拟器上必发 OOM 崩溃；此外，备份若篡改注入“满分≤0”、“权重<0”或“缺考但带分”的非法业务状态，仅靠 JSON 类型验证无法拦截，会导致趋势图除零崩溃或加权总分错乱。
*   **修复**：采用流式解析（如 `JsonReader`）边读边验；落库前在临时表或内存索引中补充业务不变量校验（满分>0、权重≥0、缺考态分数必为 NULL、Long 百分之一分未溢出）。
*   **测试**：在 `MaxHeap <= 192MB` 的模拟器上流式导入 95MiB 合成 JSON 不崩溃；注入“满分=0”和“缺考却有分”的畸形 JSON，断言在确认替换前被拦截报错且原库无损。

**2. 进程强杀（Force-Stop）与版本升级下的草稿及文件孤儿**
*   **风险**：1→2 升级新增“每场年级”字段，若旧版本 1 遗留未提交草稿，升级后读取可能因 Room 迁移未覆盖草稿结构而崩溃，或提交时丢失幂等性；ViewModel 虽防住了 `recreate`，但 PDF 生成或写 3 份安全副本途中遭遇外部 `force-stop`，重启后会遗留半写坏文件（0字节/残缺）占据配额，且 UI 无法感知上次任务已死。
*   **修复**：明确草稿表（或持久化文件）的 Room 迁移脚本（版本 1→2 补齐可空年级列）；文件写入必须遵循“写 `.tmp` 临时文件 → `fsync` → 原子 `rename`”流程；冷启动初始化时清理全部 `.tmp` 孤儿文件，并将残留的“进行中”持久化状态重置为中断失败。
*   **测试**：在 APK 1 中造出未保存草稿，直接执行 `adb install -r` 升级到 APK 2，打开继续编辑并保存成功；在导出 200 页 PDF 耗时中途执行 `adb shell am force-stop`，重启后断言目录无 `.tmp` 残留、安全副本列表无损坏项。

**3. 恢复完整替换后 UI 内存态悬空（Dangling State）**
*   **风险**：“SavedStateHandle 保存当前孩子和查询”、“历史锚点保留”以及“草稿 FIFO 队列”与“恢复完整替换”直接冲突。若恢复的备份中不包含当前选中的孩子 ID 或锚点考试 ID，或恢复时后台草稿队列仍在异步 CAS 写入，会导致恢复后 UI 白屏、外键崩溃或旧草稿脏写进新库。
*   **修复**：备份恢复事务提交的同时，必须原子性递增全局 `generation` 令牌，强制排空/作废所有进行中的草稿 FIFO 队列；校验 `SavedStateHandle` 中的孩子 ID 与历史锚点 ID 是否存在于新库，若不存在则自动回退至新库首个孩子及列表顶部。
*   **测试**：选中孩子 B 并停留在某历史锚点，同时触发草稿慢速写入，此时恢复仅含孩子 A 的备份；断言旧草稿写入被 CAS 拒绝，UI 自动切至孩子 A 首页且无崩溃。

**4. “复用上一场”在历史补录与旧数据升级下的基准错乱**
*   **风险**：修复 1 允许补录/修改历史考试年级，版本 1 旧数据无年级。若“上一场”仅按数据库自增主键（插入序）而非“考试实际日期+同年级口径”获取，家长在补录一年前的旧考后，下次录最新考试会错误复用一年前的科目与满分；且单科删除若已被旧考试引用，复用逻辑可能崩溃或带出脏数据。
*   **修复**：严格定义“上一场”查询 SQL 为“当前孩子下、状态非草稿、按考试日期降序（同日按 ID 降序）的第一条记录”，且明确过滤掉已软停用/归档的科目。
*   **测试**：在已有 10 场合成考试基础上，补录一场日期最早的历史考试（使用不同满分），随后新建今日考试，断言复用的是最新日期考试的科目与满分，而非刚插入的历史补录记录。

**5. 加权合计与趋势得分率的 BigDecimal 除零及舍入契约缺失**
*   **风险**：缺考/未录入不当作 0 分。若某场考试所有科目均为“缺考/未录入”，或有效科目的权重之和为 0，计算加权合计与 0–100 趋势得分率时，`BigDecimal.divide` 未指定 `RoundingMode`（遇到 1/3 等无限循环小数）或除数为 0，会直接抛出 `ArithmeticException` 导致首页/图表崩溃。
*   **修复**：硬性规定所有 `BigDecimal` 除法统一使用固定精度与 `RoundingMode.HALF_UP`；当单场考试有效计分科目数为 0 或有效总权重为 0 时，总分及得分率返回特定空状态（趋势图作断线处理），严禁执行除法。
*   **测试**：构造满分 300 得分 100（得分率 33.333...%）及全场全科“缺考”的极端考试记录，渲染首页、详情与趋势图，断言无 `ArithmeticException` 且全缺考场次在趋势图中正确断线。

**6. 200 页 PDF 渲染内存峰值与双倍大字/窄屏排版重叠**
*   **风险**：验收要求 199/200/201 页边界且超过限额不静默截断，同时支持 320dp 窄屏与 2 倍大字。若使用 Android 原生 `PdfDocument` 在单次循环中高频创建 Bitmap 或复用受当前 2 倍字体 `Configuration` 污染的 `Canvas`/View 测量，在 API 26/30 上渲染到 150 页左右极易 Native OOM，或导出的 A4 表格文字严重重叠覆盖。
*   **修复**：PDF 渲染必须使用独立于设备屏幕缩放（固定 DPI 与字号）的脱离屏幕绘制上下文，逐页创建并立即 `finishPage` 释放单页资源；对超过 200 页上限的请求，在冻结输入预估阶段即拦截并弹窗提示缩小日期/科目范围，而非渲染到 20
